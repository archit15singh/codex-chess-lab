# Sequence memory trials

This supplementary experiment compares ordinary retained conversation context
(`internal`) with an external copy of that same actor's prior, uncorrected
checkpoint responses (`record`). It measures sequence transcription and recall;
it does not measure native browser execution, Elo, or model-weight learning.
Overlapping sequences share a source-game/family cluster.

The controller selects one sealed player sequence. The private manifest contains
only that sequence, its condition and input/source commitments. Preparation reads
no evaluator answers. Each sequence has four checkpoints: 6/12/18/24 or
10/20/30/40. Both conditions receive every intervening image in order. Frame 0 and
initial rules appear only with the first stage. A later stage contains only frames
since the previous checkpoint. It supplies no current corrected rules or history.

Use a frozen, reviewed mechanical runtime containing `memory_trial.py` and
`position_trial.py`. The mechanical module imports no chess library and invokes
no engine or legality function. Its reuse of the static validator checks response
format only, by substituting a dummy UCI string. Offline scoring requires the
isolated chess evaluator environment. Snapshot/host tool audits remain necessary:
file allowlists and prompt instructions do not create a filesystem sandbox.

## Controller operations

Use a new private destination, with no retries or replacement sequence IDs:

```sh
python3 -m chesslab.memory_trial prepare CORPUS SEQUENCE_ID internal TRIAL_DIR
python3 -m chesslab.memory_trial open TRIAL_DIR
python3 -m chesslab.memory_trial submit TRIAL_DIR 1 RESPONSE_FILE
python3 -m chesslab.memory_trial open TRIAL_DIR
```

Use `record` for the other condition. Keep the same fresh actor context for the
four stages of one sequence; start a separate fresh context for its paired
condition. Randomize the predeclared condition order outside this mechanical
module. No actor, outcome, lesson, or final corpus is generated by this command.

The controller alone runs `prepare` and `open`. Give the actor only the returned
stage delivery JSON, its explicitly named PNG files, the neutral schema/brief,
and permission to write its current answer and invoke the submission CLI. Do not
give it the trial manifest, corpus directory listing, source sequence index,
evaluator files, stop/response records, earlier response paths, or future stage
paths. The internal condition retains ordinary conversation context but may not
reread earlier response files. Only the record condition receives
`own_prior_responses` in subsequent deliveries. These are exact prior answer
bytes encoded as base64 plus a UTF-8 display string; base64 preserves even
non-UTF-8 input. There are no corrections or chess verdicts.

The first `open` for a stage persists its opening timestamp and a deadline exactly
60 seconds later, before returning delivery. Repeated `open` returns that same
record and deadline. Count host delivery/dispatch and image loading inside this
budget; preserve host startup/delivery timing separately in the controller trace.
No stage opens before the previous response. The first response is immutable,
including a malformed or late one. A late/malformed response stops the sequence;
an `open` after an unanswered deadline records a missing-response stop. Preserve
all partial evidence and do not launch replacements. Exclusive mutation locks
prevent interleaved operations. After a process crash, a lock is never stolen on a
timeout: confirm that execution has authoritatively ended before manually
removing only the stale `.mutation.lock`. A partially created stage or preparation
is an auditable failure, not permission to overwrite it.

## Actor response

Submit exactly these seven keys as JSON, with all 64 algebraic squares present in
`piece_map`:

```json
{
  "last_move_uci": null,
  "piece_map": {"a1": "?", "a2": "?"},
  "side_to_move": "unknown",
  "confidence": 0.0,
  "castling": {
    "white": {"kingside": "unknown", "queenside": "unknown"},
    "black": {"kingside": "unknown", "queenside": "unknown"}
  },
  "en_passant_square": "unknown",
  "recall": {"d4": "?", "e5": "?"}
}
```

The displayed `piece_map` is abbreviated and is not a valid submission. Its real
keys are every square a1..h8. Values are uppercase White/lowercase Black piece
symbols (`PNBRQKpnbrqk`), `.` for empty, or `?` for unknown. `last_move_uci` is the
most recent ply in coordinate UCI, with an optional lowercase promotion suffix;
use null if unknown. `side_to_move` is white/black/unknown. Castling values are
booleans or `unknown`. En passant is an algebraic square, null for none, or
`unknown`. Confidence is finite and within 0..1. `recall` reports d4 and e5 at the
**previous checkpoint**, using frame 0 for the first stage. No reasoning prose is
required. The CLI stage argument records the stage; do not add it to the answer.
Submission stdout contains only `recorded`, `late`, and `format_valid`.

## Offline evaluation

After the operator verifies authoritative completion of the actor handle, retain
a separate controller evidence file and run:

```sh
.venv/bin/python -m chesslab.memory_score TRIAL_DIR SCORE_DIR \
  --actor-completed --completion-evidence CONTROLLER_COMPLETION_FILE
```

The flag is an operator attestation, not an automatic host-status check. Scoring
uses an exclusive new output directory and preserves source/input hashes. The
score output must be outside the trial directory, in a disjoint directory tree;
neither directory may contain the other. This is checked before creating output,
including resolved symlink paths. All work after output reservation, including
the first input hash read, is covered by failure recording. It
requires a unique sealed final-family history matching every delivered frame;
replays all selected plies and validates frame FEN/rules against that legal line.
It verifies assigned frame ranges, initial metadata, condition-specific own-record
bytes, persisted deadlines, sequential chronology, exact raw response/base64/hash,
and parsed-response consistency. No engine is used.

Every assigned sequence retains a denominator of four checkpoints. Missing,
malformed, late and unopened stages remain visible. The primary endpoint is an
on-time exact final-checkpoint occupancy map; a missing or invalid final answer
fails that endpoint. Late valid answers retain secondary fidelity scores while
failing on-time endpoints. Square accuracy/unknowns, last-ply UCI, d4/e5 recall,
turn, castling flags, en-passant, confidence and response latency are reported
separately. Integrity failures produce a preserved failure record with the same
four-checkpoint denominator; do not quietly drop or replace them. Statistical
analysis must retain paired conditions and cluster by source family/game.
